## 详细描述

**判据住在被核对的文本里时，它会找到自己。**

一个反向样本（负样本）想证明的是「判据能失手」：把一个锚改成体内不存在的串，
要求核对器报出。样本写成完整字面量 —— 而这个字面量恰好就落在被搜索的那段文本里。
于是核对器在源码文本里找到了这个串，判「锚在体内」，问题数为 0；样本断言的
「核对器必须报出」不成立。

**样本测的不再是诊断力，而是「我会不会在自己的源码里找到自己写的字」** ——
一个永远为真的命题。

这里真正的一般形态不是「字符串撞了」，而是：**负样本的有效性依赖一个隐含前提
（哨兵串不出现在被搜索的文本中），而没有任何地方在检查这个前提**。前提只存在于
写样本的人的记忆里。凡是「靠人记得」的前提，都会在被忘记的那一次静默失效。

失效方向值得单独强调：负样本假绿比**没有**负样本更糟。没有负样本时，我们知道自己
没证明「判据能失手」；负样本假绿时，它**看起来已经证明了**。判据的诊断力被一项恒真
的样本认证过，此后不会有人再问「这条判据真的会报吗」。

同一根因的其它可能变体（以下三条是**按根因推演**的形态，非本次实测记录，
使用前请在自己的仓库里核实）：

- 判据扫的文本包含**它自己的说明文字**，于是「违规串已清除」被说明里的举例冒充；
- 负样本把配置改成一个「不可能取值」，而那个取值恰好在别处作为缺省值存在；
- 探针把文件路径改成一个「不存在的路径」，而该路径被日志或注释原样引用。

## 根因链

1. **现象层**：断言「核对器必须报出 X」失败，但问题数为 0 —— 看起来像判据太弱，
   实际是样本无效。
2. **直接原因**：哨兵串写成完整字面量，且这段代码就在被搜索的体内，核对器在源码
   文本里找到了它。
3. **为什么样本会这么写**：负样本的思路是「造一个体内不可能出现的串」，写出完整
   字面量是最自然的写法。**自指不是失误，是默认写法** —— 除非有人刻意把哨兵与
   被搜索文本分开，否则两者必然重合。
4. **为什么没有人补上这个前提**：前提（哨兵不自指）是**关于样本自身的性质**，不是
   关于被测对象的性质。测试代码通常只断言被测对象，很少有人对自己写的样本下断言；
   而这里的样本恰恰需要一个对自身的断言。
5. **为什么失效不可见**：假绿方向。问题数为 0 与「一切正常」在输出上完全一样，
   而样本的断言失败又容易被归因为「判据太弱」→ 人去改判据，而不是去看样本。
   改错方向的后果是：真正的诊断力问题被掩盖得更深。
6. **本质原因**：**判据既读文本又住在文本里时，「不存在」这个概念在它自己的作用域
   内不可表达。**要在自身的作用域里表达「不存在」，必须借助构造（拼接）或换作用域
   （另一个文件的对象）。

## 代码示例

### ❌ 错误示例

```python
# <project>/<module>/criteria.py
import inspect


def anchor_problems(fn) -> list[str]:
    """判据：函数声明的锚串必须出现在它自己的源码文本里。"""
    declared = fn.anchor
    if declared not in inspect.getsource(fn):
        return [f"{fn.__name__}: 声明的锚 {declared!r} 不在体内"]
    return []


def guarded_rule(text: str) -> str:
    """被核对的函数。"""
    SENTINEL = "anchor-absent-7f3a"   # ❌ 哨兵字面量就写在被搜索的体内
    return text.replace(SENTINEL, "")
```

```python
# tests/test_criteria.py
from <module>.criteria import anchor_problems, guarded_rule


def test_reverse_sample_reports_missing_anchor() -> None:
    # 反向样本：把锚换成一个「体内不该存在」的串，要求核对器报出
    guarded_rule.anchor = "anchor-absent-7f3a"   # ❌ 与体内那行字面量是同一个完整串
    assert anchor_problems(guarded_rule) != []   # 问题数为 0 → 断言失败（假绿）
```

### ✅ 正确示例

```python
# <project>/<module>/criteria.py
import inspect


def anchor_problems(fn) -> list[str]:
    declared = fn.anchor
    if declared not in inspect.getsource(fn):
        return [f"{fn.__name__}: 声明的锚 {declared!r} 不在体内"]
    return []


def guarded_rule(text: str) -> str:
    """被核对的函数。"""
    return text.strip()          # ✅ 体内不再出现任何哨兵字面量
```

```python
# tests/test_criteria.py
import inspect

from <module>.criteria import anchor_problems, guarded_rule

# ✅ ① 拼接构造：完整串不以字面量形式出现在被搜索的文本里
SENTINEL = "anchor-absent" + "-7f3a"


def test_reverse_sample_reports_missing_anchor() -> None:
    # ✅ ② 前置断言：把「哨兵没自指」从「写的人要记得」变成被检查的前提
    assert SENTINEL not in inspect.getsource(guarded_rule), (
        "哨兵自指：完整串出现在被搜索的体内，这条负样本测不到任何东西 —— 先修样本"
    )

    guarded_rule.anchor = SENTINEL
    assert anchor_problems(guarded_rule) != [], "核对器没有报出体内不存在的锚"
```

```python
# tests/test_criteria.py（续）
from <module>.fixtures import OTHER_NODE        # 另一个文件里的对象，其源码不含任何哨兵


def test_reverse_sample_via_foreign_object() -> None:
    # ✅ ③ 更稳的做法：哨兵所在的文本与被搜索面不相交，从结构上避开自指
    OTHER_NODE.anchor = SENTINEL
    assert anchor_problems(OTHER_NODE) != []
```

## 对应失败模式

对应 `coverage_vacuum`（覆盖真空）：负样本是覆盖「判据会不会报」的那条判据，它假绿
意味着**判据的诊断力本身没有覆盖** —— 有一个判据在场，但它能否失手从未被检验。
这里没有「测试没写」的表象（样本明明写了、也跑了），所以真空更隐蔽。

不归 `hallucination`：核对器没有声称任何不存在的东西，它忠实地报告了它在文本里
找到的串 —— 错的是样本构造，而不是判据在虚构事实。

**置信度说明**：给 0.85。机制（自指 → 负样本恒假绿）与三条修法都明确，且修法可判定：
拼接构造使完整串不在被搜索文本里，前置断言把隐含前提变成显式断言 —— 两条都能通过
「把样本改回去，用例必须变红」自证。未给更高分是因为源记录只记 1 次发生；另外源记录
未明确给出被搜索文本的确切边界（函数体还是整个文件），此处按 detection_trigger 的
「body 长度与你刚写进该函数的代码同量级」理解为**函数级**，该理解属**推断 / 待复核** ——
若实际边界是整个文件，修法不变（拼接构造与前置断言在两种边界下同样成立）。

## 改进方向

- **短期**：哨兵串一律用拼接构造；在变异前加 `assert sentinel not in body`，让自指
  在样本自己这一层被拦下。
- **短期**：给负样本加一条自证要求 —— **把负样本改回「应当失败」的形态，它必须真的
  失败**；否则这条样本不构成对判据诊断力的任何证据。
- **长期**：把「判据 / 样本 / 被搜索文本」三者的作用域在结构上分开。负样本引用**另一个
  文件**里的对象，自指在结构上不可能发生，比靠约定可靠。
- **长期**：评审清单加一问 ——「这个负样本凭什么认为自己应当失败？」不能一句话答出来
  的负样本，按未覆盖处理。
