## 详细描述

当一个渲染器用手写字段映射而不是全量遍历时，「不渲染」就变成了**默认行为**而不是一次
显式决定：没有人做过「这个字段不渲染」的判断，它只是没被写进那张表。于是字段被静默丢弃，
而丢弃的是对外形态 —— **对外形态就是契约**，下游只认渲染产物，不认源文件。

本例的后果恰好覆盖了两类消费方，而且都无声：

- 一个检查器只识别由被丢弃字段渲染出的某类行（形如 `- capability:`）→ 对本仓**每一份**
  该类工件**恒 SKIP**；
- 人工确认环节读的正是这份渲染产物 → 用户在门外看不到本次声明的内容：**4 个整节**消失
  （约束、非目标、干系人、风险面），其中包括 **6 条约束（含硬约束）** 与 **3 条风险及
  缓解**。

这里最值得记住的一句话是：**「检查器不报错」有两种可能 —— 被检对象干净，或者检查器根本
没在跑；这两种在输出上长得一模一样。** 一个恒 SKIP 的检查器和一个永远通过的检查器，在
汇总里都是「没有红灯」；而如果它检查的字段本身就被渲染器丢掉了，那它连「看到过」的机会
都没有。同理，人工确认少看了 6 条硬约束，也不会产生任何提示 —— 读者只能看到「这次改动
没有声明约束」。

两个后果共享同一个根因，但修复面不同：**检查器恒 SKIP 需要把字段渲染出来**（让它有东西
可读），**读者看不到约束需要把字段渲染出来并列入保真测试**（让下次再丢会变红）。这也
说明了为什么仅仅「修好这一次」不够 —— 手写映射表的默认行为没变，下一个新增字段会以完全
相同的方式消失。

## 根因链

1. **现象层**：检查器对整类工件恒 SKIP；人工确认的输入里少了整节内容。两者都不报错，
   因此都没有被当成缺陷。
2. **直接原因**：渲染器的字段映射是手写的白名单，未被列入的顶层键被静默丢弃（本例丢
   `constraints` / `non_goals` / `stakeholders` / `risk_areas` 四个整节）。
3. **为什么会出现**：「不渲染」是默认行为。写渲染器时只想着「要把哪几个字段渲染出来」，
   而没写下「哪些字段有意不渲染、为什么」。缺少后半句时，任何新增字段都自动落入「不渲染」，
   且这个决定没有留下任何痕迹。
4. **为什么没被兜住**：没有保真测试。既有的检查都在渲染产物内部做文章（在产物里找某个
   形态），而没有任何检查把**源文件**与**渲染产物**对起来。检查器恒 SKIP 与检查对象干净
   在输出上同形，于是这条通路上的失效没有任何可观测的差异。
5. **本质原因**：**对外形态即契约**。渲染产物是下游唯一的输入面，源文件里写了什么不影响
   下游能不能看见。把「渲染哪些字段」交给一张手写表且不做保真校验，等于让契约的覆盖面
   由那张表的当前内容决定 —— 而它会随时间悄悄缩小。

## 代码示例

### ❌ 错误示例

```python
# ❌ 渲染器用手写映射：只映射 4 个键，其余静默丢弃
def render_source(source: dict) -> str:
    lines = []
    for key in ("why", "what_changes", "capabilities", "success_criteria"):   # ❌ 手写白名单
        lines.append(f"## {key}\n{source.get(key, '')}")
    return "\n".join(lines)
    # constraints / non_goals / stakeholders / risk_areas 四个整节在此处消失，无任何提示


# ❌ 检查器只在渲染产物里找某个形态：字段被丢弃 → 恒 SKIP
def check_scope(rendered: str) -> str:
    rows = [ln for ln in rendered.splitlines() if ln.startswith("- capability:")]
    if not rows:
        return "SKIP"          # ❌ SKIP 与 PASS 一样不刺眼；从未有人数过它跳过了多少份
    ...
```

### ✅ 正确示例

```python
RENDERED_KEYS = frozenset({"why", "what_changes", "capabilities", "success_criteria",
                           "constraints", "non_goals", "risk_areas"})

# ✅ 「有意不渲染」清单：每个键写明理由与消费者 —— 豁免是可审的显式编辑，不是默认行为
EXEMPT_KEYS = {
    "stakeholders": "读者不需要；消费方：无（仅内部检索用）",
}


def render_source(source: dict) -> str:
    unclassified = set(source) - RENDERED_KEYS - set(EXEMPT_KEYS)
    if unclassified:
        # ✅ 新增字段必须被显式归类，不允许静默丢弃
        raise UnclassifiedFieldError(sorted(unclassified))
    return "\n".join(
        f"## {k}\n{source[k]}" for k in RENDERED_KEYS if k in source
    )
```

```python
def test_every_leaf_of_every_source_is_findable_in_its_render(source_root, render_root):
    # ✅ 保真测试：对仓内每一份源文件，逐个顶层键取叶子内容，回到渲染结果里找。
    #    刻意不读渲染器的映射表（否则与渲染器同义反复）。
    for src_path in sorted(source_root.glob("*/<source>.md")):
        source = parse_frontmatter(src_path)
        rendered = (render_root / src_path.stem / "<rendered>.md").read_text(encoding="utf-8")
        for leaf in iter_leaf_strings(source):
            assert leaf in rendered, (src_path, leaf)          # 找不到即红


def test_persisted_artifact_matches_a_fresh_render(source_root, render_root):
    # ✅ 防止「代码修了、仓里那份产物还是旧的」
    for src_path in sorted(source_root.glob("*/<source>.md")):
        fresh = render_source(parse_frontmatter(src_path))
        assert fresh == (render_root / src_path.stem / "<rendered>.md").read_text(encoding="utf-8")
```

关键在保真测试的写法：它从**源文件**出发遍历叶子内容，而**不去读渲染器的映射表**。若反过来
按映射表逐键检查，就与渲染器同义反复 —— 映射表里没有的键，测试也就不会去查，正是本例要
防的那个盲区。

## 对应失败模式

**(j) 覆盖真空（coverage_vacuum）**：源文件里写着的约束与风险没有任何测试或检查覆盖到
「它们能不能到达消费方」，渲染器丢字段这件事本身也没有任何判据。这个真空的具体形态是
**检查器对整类工件恒 SKIP** —— 它有判据、有代码、每次运行都出现在汇总里，但从未真正检查
过任何一份输入。这正是覆盖真空最隐蔽的形态：不是「缺一条判据」，而是**判据在，覆盖面不在**。
不归 `content_quality`：丢的不是内容质量，是契约面（对外形态少了整节内容）。

**置信度说明**：给 0.85。后果可直接量化且来自源记录：**4 个整节**消失，随之不可见的是
**6 条约束（含硬约束）** 与 **3 条风险及缓解**，检查器对本仓**每一份**该类工件恒 SKIP；
修法给出了一条可执行且不易写成同义反复的保真测试写法（从源文件遍历叶子内容，不读映射表），
使这条经验具备可持续的自动化防线。未给更高分有两个原因：一是源记录只记 1 次；二是源记录
未记录该检查器恒 SKIP 持续了多久、覆盖了多少份工件，也未记录下游是否已有人据此做过判断，
故不声称影响面，只记录「每一份」这一范围表述。

## 改进方向

**短期**：
- 把被丢弃的字段渲染出来 —— 对外形态即契约，按消费侧能解析的形态写，而不是「反正源文件
  里还在」。
- 建立「有意不渲染」清单：每个不渲染的键写明理由与消费者。把豁免从静默行为变成可审的
  显式编辑；对未归类的键直接报错。
- 加保真测试与「落盘产物 == 当前源重新渲染」断言；前者防新的字段被丢，后者防修了代码而
  产物还是旧的。

**长期**：
- 把渲染器的字段处理从「手写白名单」改为「全量遍历 + 显式豁免」，让「不渲染」永远是一次
  决定，而不是一次遗漏。手写表会随时间缩小覆盖面，而缩小是无声的。
- 在输出规范里把**跳过与通过分开显示**：SKIP 必须计数并带原因。一个恒 SKIP 的检查器在
  汇总里应当刺眼，而不是与「检查对象干净」同形。
- 对所有「对外形态由某个映射 / 模板 / 白名单生成」的系统，把保真测试列为例行要求：源与
  产物之间必须有一条不经过映射表本身的包含性检查。
