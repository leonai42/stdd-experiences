## 详细描述

**按类型分级豁免，等于按类型预留盲区。**

一台审计工具为了减少噪音，对某一类条目（例：只承载反向声明的那一类）整类跳过核对。
于是那条被豁免的条目里躺着一个**指向不存在标识符的锚** —— 一个在任何其它类型下都会
被立刻报出的错误 —— 而核对器对它**一言不发**。

根因不是「忘了核对这一条」，而在于**豁免的划分维度与损坏的分布维度不一致**：

- 豁免是按 **class** 划分的；
- 「容易被写坏的东西」（手抄的锚、点名的路径、反向声明）**不按 class 分布**。

给一类条目开后门，等于给「弄坏那一类」开后门 —— 而破坏者甚至不需要什么破坏意图，
**不按 class 分布的损坏自己就会落进被豁免的那一类里**。

### 更糟的一种情形：核对器的职责恰是「判据自己受审计」

当这台核对器的输出是别的判据的输入（元判据 / metajudge）时，盲区的后果被放大两级：

1. **没有下游能发现它。** 别的检查相信它的结论；它的绿会被继承，而它的沉默不会被
   任何东西读出来。
2. **盲区出现在最不该出现的位置。** 一台专门用来「让判据受审」的机器自己留了后门，
   意味着整条信任链的根节点是未受审的。

### 豁免清单本身也需要一条判据

「哪些类被豁免」写在代码里，而**没有任何检查会把「弄坏被豁免的那一类」当成失败**。
于是豁免是一条不会被质疑的静默通道。这就是为什么修法里必须包含一条可证伪样本：
**豁免的合法性不能由写下豁免的人自证，只能由「弄坏它会被报出」来证明。**

## 根因链

1. **现象层**：被豁免那一类里的锚指向不存在的标识符，核对器返回 0 个问题。
2. **直接原因**：核对循环按条目类型跳过了一整类。
3. **为什么豁免会按类型分**：按类型豁免写起来最省力（一行 `continue`），且动机是正当的
   —— 减少噪音、减少误报。**豁免的动机正当，不等于豁免的边界正确。**
4. **为什么这类豁免特别危险**：豁免的划分维度（class）与损坏的分布维度（手抄的锚、
   点名的路径）不一致。损坏不会按 class 分布，所以被豁免的那一类里**必然**会积累
   未经核对的错误 —— 只差触发的时间。
5. **为什么没人复核它**：豁免清单没有判据在管。要做的事（「弄坏被豁免的那一类」）
   没有任何地方要求被声明，于是它既不会被检查，也不会因为没人做而报错。
6. **为什么后果被放大**：核对器的职责是「判据自己受审计」。它的绿变成别的判据的输入，
   盲区不暴露、只被继承。**链条上越靠近根节点的豁免，影响面越大，而它的漏检也越
   不可见。**
7. **本质原因**：**任何「按类别跳过」的规则，都必须回答「被跳过的那一类，谁来管」。**
   答不上来的豁免不是优化，是把覆盖面积按类别切走了一块。

## 代码示例

### ❌ 错误示例

```python
# <project>/<module>/audit.py
from typing import Iterable

# ❌ 按条目类型分级豁免：这一整类不参与核对
EXEMPT_KINDS = {"declaration_only"}     # 例：只承载反向声明的那一类条目


def audit_entries(entries: Iterable[Entry]) -> list[str]:
    problems: list[str] = []
    for e in entries:
        if e.kind in EXEMPT_KINDS:
            continue                    # ← 给「弄坏那一类」开后门
        if e.anchor not in IDENTIFIERS:
            problems.append(f"{e.id}: 锚指向不存在的标识符 {e.anchor!r}")
    return problems
```

```python
# tests/test_audit_probe.py
def test_probe_exempt_kind() -> None:
    # 探针：把被豁免那一类的锚改成不存在的串
    broken = Entry(id="E-9", kind="declaration_only", anchor="no-such-identifier")

    # ❌ 返回 0 个问题 —— 核对器对它一言不发
    # 这条断言「通过」正是盲区的证明：同样一个错误，换个 kind 就会被报出
    assert audit_entries([broken]) == []
```

### ✅ 正确示例

```python
# <project>/<module>/audit.py
# ✅ 若确需保留豁免，逐条登记理由（不按类型批量豁免）；
#    ✅ 豁免只意味着「已知且已登记」，不意味着「不再核对」
EXEMPT_IDS: dict[str, str] = {
    # "E-007": "该锚由外部工具在运行时注入，静态语料里查不到"
}


def audit_entries(entries: Iterable[Entry]) -> list[str]:
    problems: list[str] = []
    for e in entries:
        # ✅ 唯一允许的跳过条件：它**根本没声明这个字段**（而不是它属于某个类型）
        if e.anchor is None:
            continue
        if e.anchor not in IDENTIFIERS:
            note = EXEMPT_IDS.get(e.id)
            problems.append(
                f"{e.id}: 锚指向不存在的标识符 {e.anchor!r}"
                + (f"（已登记豁免：{note}）" if note else "")
            )
    return problems
```

```python
# tests/test_audit.py
def test_no_kind_is_silently_exempt() -> None:
    # ✅ ② 每条豁免都配可证伪样本：逐类弄坏一条，核对器必须点名报出
    all_kinds = sorted({e.kind for e in load_corpus()})   # ✅ 从语料推导，不手抄
    assert all_kinds, "语料为空：先确认扫描面，否则下面的循环是空的"
    for kind in all_kinds:
        broken = Entry(id="E-9", kind=kind, anchor="no-such-identifier")
        assert audit_entries([broken]), f"{kind} 整类不参与核对 —— 豁免制造了盲区"


def test_exemptions_are_audited_too() -> None:
    # ✅ ③ 豁免清单本身也要有判据在管：每条豁免必须有理由，且指向真实存在的条目
    for entry_id, reason in EXEMPT_IDS.items():
        assert reason.strip(), f"{entry_id} 被豁免但没有登记理由"
    assert set(EXEMPT_IDS) <= {e.id for e in load_corpus()}, "豁免清单里有不存在的条目"
```

## 对应失败模式

对应 `coverage_vacuum`（覆盖真空）：被豁免的那一整类条目有判据（核对器在场、循环也写了），
却没有覆盖 —— 而「有核对器」这件事让真空不可见。这里的真空是按**类别**切出来的，
所以它比单条漏检更系统：不是某个对象没被看过，而是**某一整类对象从来不在扫描面内**，
且这个切口写在一个不会被质疑的地方。

不归 `tool_misuse`：核对器被正常使用，没有用错参数或命令；缺口来自核对器自身的
作用域设计。也不归 `contract_gap`：这里没有两侧实现不一致 —— 是**一侧少了一半面**。

**置信度说明**：给 0.85。盲区的暴露方式与三条修法都来自源记录且可判定：探针「把被豁免
那一类的锚改成不存在的串 → 0 个问题」一次运行即见分晓；修法②「弄坏它必须被点名报出，
否则判据自己红」本身就是一条可执行的断言；修法③把豁免清单也纳入受审面，闭合了
「豁免无人管」这个次级缺口。未给更高分是因为源记录只记 1 次发生，且「其余按类型分级的
豁免各自是否合理」，源记录只提出要**逐条复核**、**未给出复核结论** —— 除本条已证实的那
一处之外，其余豁免的存在与处置属**待复核**，示例中的逐条登记写法为示意。

## 改进方向

- **短期**：把核对循环从「某一类」放宽到「任何声明了该字段的条目」。唯一允许的跳过条件
  是「没声明这个字段」，不是「属于某个类型」。
- **短期**：给每条豁免配一条可证伪样本 —— 弄坏它必须被点名报出，否则判据自己红。
  豁免的合法性只能由「弄坏会被报出」证明，不能由写下豁免的人自证。
- **长期**：复核其余按类型分级的豁免，逐条问「豁免的那一类，谁来管」。答不上来的取消
  豁免；确需保留的改成逐条登记理由，并让探针继续跑。
- **长期**：把「越靠近信任链根节点的核对器，其自身覆盖越要完整」作为评审原则。元判据
  （核对其它判据的判据）自身留白时，盲区不会在下游暴露，只会被继承。
