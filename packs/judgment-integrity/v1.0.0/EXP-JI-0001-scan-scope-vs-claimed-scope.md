## 详细描述

**判据的扫描面必须与它声称核对的面同宽。**这句话听着像同义反复，实际极难做到，因为
扫描面是写死的代码（正则、子串、`grep` 参数、文件清单），而声称面是一句散文 ——
两者之间没有任何机制保证对齐，对齐全靠写判据的人当场想清楚「这句话管多大」。

不同宽会朝两个方向失效，**两向都在同一次变更里被实测到**：

- **窄向 → 假绿（静默放过）**。判据用 `git grep` 扫消费者，而 `git grep` **默认不搜索
  未跟踪文件**；构建期间新建的消费者在提交前就是未跟踪的，于是判据看不见它。
  绿不是因为那里干净，而是因为**没看那里**。
- **宽向 → 假红（把合法文本当成违规）**。正向判据按**子串**扫一个目录，而同一轮新写的
  一处 docstring 引用了判据文件自己的名字（恰好含该子串）→ 全量回归当场变红。
  红得对，但原因是**取材面宽于声称面** —— 那个文件读的是另一份配置。

**两侧的处置方向相反**，这是本条最容易被做错的地方：窄向要扩扫描面（加 `--untracked`），
而宽向**不能**靠收窄扫描来消除 —— 收窄会把窄向的假绿重新引回来。宽向的正确处置是
**扩声称面**：把「命中即违法」改成「命中即必须被分类，且提及须带理由」。

同一个形态还会以「宽度差」本身出现，而不只是「扫 A 而实际是 B」：

- 一条声明说某个数值「只有一个来源」。判据扫的是**实现侧**，而这句话读者会理解成**全仓**。
  实测：实现侧确实成立，但全仓另有三处活副本仍写着旧取值，其中一处更刺眼 ——
  同一段里一边指向权威源，一边给出与权威源**相反**的取值。判据绿不是因为它看错了，
  而是因为它与这句话**管的范围不同宽**：判据管实现，宣称管全仓。而这次那份副本是**指令**，
  是执行者照着做的东西。
- 另一个字段的唯一读者是**判据自己**，生产端零消费方；呈现层反而绕开解析入口、直接读
  缺省值。于是「缺失即明说」这条要求在 API 层成立、在**用户可见面**上并未达成 ——
  又一次宽度差，而且这次是在**为治这个病而新建的模块**里长出来的。

**边界随介质而变**，处置规则不能一套通用：

| 介质 | 什么会被误读成「主张」 | 处置 |
|---|---|---|
| 散文类文档 | 原文、注释、引用 | **不复述原文**（墓碑只说「曾有一句假话」并指向变更台账编号） |
| 代码 | 只有可执行行 | **扫描时排除纯注释行**（注释创建不了副作用，排除是把扫描面收到与声称面同宽） |

**另有实测的规模差**：一次变更的计划里声称「4 处活引用」，按判据实测扩到 **20 处** ——
含下发给下游的指令与悬空的引用条目，其中一条还是**会被执行到**的路径。手抄的不只是
「投递什么」，还有「查什么」；**范围由人手抄 ⇒ 范围收缩是静默的**。同一份集合在本仓
曾有三处手抄清单，各自声明「这就是要下发的集合」，而真正投递的那份已实测漂移两处：
漏投一个一直在源头的文件，以及一个被正文以「参见 …」引用的共享文件 —— 下游于是读到
一条**指不到实处的路径**。

## 根因链

1. **现象层**：判据全绿，而它声称的验收判据实测未达成；或者判据变红，而违规并不存在。
2. **直接原因**：判据的扫描面（正则 / 子串 / grep 参数 / 文件清单）是写死的，声称面是散文，
   两者不同宽。
3. **为什么没人发现（窄向）**：**范围收缩是静默的**。范围变了，用例依旧全绿，覆盖可能
   已经归零 —— 没有任何信号提示「你少看了一块」。绿得越久，它越像一项资产。
4. **为什么会留副本**：多副本分发让同一份内容存在多份拷贝，改一份留一份；判据扫的那份
   不是真正被消费 / 下发的那份。而副本是手抄的，于是「副本与基准」之间也没有对齐判据。
5. **为什么宽向也会算错**：子串命中不区分「主张」与「提及 / 注释 / 文件名引用」，于是
   写判据的人要为自己写下的**无关字面量**负责 —— 红得对，理由却是错的。
6. **为什么必须两侧都有 Control**：只有正向 Control 时判据可能恒绿，只有反向时可能恒红，
   而两种都长成「判据在工作」。Control 的作用是把「判据能命中」和「判据能失手」变成
   被检查的事实，而不是写判据的人的信心。
7. **本质原因**：**判据的绿只等价于它扫描的那一块的事实**。要让它等价于声称的事实，
   必须先写下一句可度量的声称面，再让扫描面与它同宽 —— 顺序不能反过来。

## 代码示例

### ❌ 错误示例

```python
import subprocess


def test_no_legacy_flag_reaches_consumers() -> None:
    # ❌ 窄向：git grep 默认不搜索未跟踪文件
    # 构建 / 生成期间新建的消费者在提交前就是未跟踪的 → 判据看不见它
    out = subprocess.run(
        ["git", "grep", "-n", "legacy_flag", "--", "src"],
        capture_output=True, text=True, check=False,
    )
    assert out.stdout == ""      # 绿，只是因为没看那里
```

```python
def test_thresholds_defined_in_one_place() -> None:
    # ❌ 宽向：子串命中面宽于声称面 —— 提及、注释、文件名引用都会被算成「主张」
    # 同一轮新写的注释引用了判据文件名（含该子串）→ 全量回归当场变红
    out = subprocess.run(
        ["git", "grep", "-rn", "thresholds", "--", "src"],
        capture_output=True, text=True, check=False,
    )
    assert len(out.stdout.splitlines()) == 1   # 红得对，但原因是取材面过宽
```

### ✅ 正确示例

```python
from pathlib import Path
import subprocess

# ✅ 扫描面覆盖全部会被消费 / 下发的副本：源码、模板、生成目录、仓内镜像
SCANNED_ROOTS = ["src", "template", "generated", "mirror"]
LEGACY_FLAG = "legacy_flag"


def _grep(pattern: str, *roots: str) -> list[tuple[str, int, str]]:
    out = subprocess.run(
        # ✅ --untracked：未跟踪的新文件同样在扫描面内（窄向的修法）
        ["git", "grep", "-n", "--untracked", pattern, "--", *roots],
        capture_output=True, text=True, check=False,
    )
    rows = []
    for line in out.stdout.splitlines():
        path, lineno, text = line.split(":", 2)
        rows.append((path, int(lineno), text))
    return rows


def _is_executable_claim(text: str) -> bool:
    # ✅ 边界随介质而变：代码里只有可执行行是主张，纯注释行创建不了副作用
    return not text.lstrip().startswith(("#", "//"))


def test_no_legacy_flag_reaches_consumers() -> None:
    hits = [r for r in _grep(LEGACY_FLAG, *SCANNED_ROOTS) if _is_executable_claim(r[2])]
    assert hits == [], f"仍有下发给消费者的活引用：{hits}"


def test_scan_can_hit() -> None:
    # ✅ 正向 Control：扫描必须能命中一个已知存在的标记（该串确实写在 src/ 的夹具里），
    # 否则「一条都没命中」既可能是干净，也可能是扫描面失效
    assert _grep("SCAN_PROBE_MARKER", *SCANNED_ROOTS), "扫描面失效：连已知标记都看不见"


def test_scan_can_miss() -> None:
    # ✅ 反向 Control：同一串放在扫描面之外必须看不见 —— 证明判据「能失手」
    assert _grep("SCAN_PROBE_MARKER", "out_of_scope_dir") == []


# ✅ 宽向的修法：扩声称面，不是收窄扫描（收窄会重新引入窄向的假绿）
MENTION_REGISTRY = {
    "src/report/notes.md:12": "说明性提及，理由：向读者指出阈值表所在处，不构成第二来源",
}


def test_every_mention_is_classified() -> None:
    for path, lineno, _ in _grep("thresholds", *SCANNED_ROOTS):
        key = f"{path}:{lineno}"
        assert key in MENTION_REGISTRY, f"未登记的提及：{key} —— 命中即必须被分类"
        assert MENTION_REGISTRY[key].strip(), f"提及缺理由：{key}"


def delivered_names() -> set[str]:
    # ✅ 副本与基准同源：交付清单从目录推导，而不是各处手抄一份
    return {p.name for p in Path("template").iterdir()}


def test_copies_are_derived_not_transcribed() -> None:
    hand_transcribed = {"a.md", "b.md", "c.md"}      # 各平台模板里手抄的那份清单
    assert hand_transcribed == delivered_names(), (
        "手抄清单与实际交付集合已漂移 —— 副本必须从目录推导"
    )
```

## 对应失败模式

对应 `coverage_vacuum`（覆盖真空）：有声称（判据要核对的事实边界），没有覆盖（扫描面
没伸到那里），而「有判据」这件事本身让真空不可见。窄向是覆盖真空的教科书形态 ——
判据在跑、日志有输出、用例全绿，唯独**要核对的那些对象从来没被看过**。

不归 `contract_gap`，是因为这里没有两侧实现不一致的问题：判据与它声称的面属于同一方，
失配发生在「代码的扫描范围」与「散文的事实边界」之间 —— 是覆盖面的问题，不是契约问题。

**置信度说明**：给 0.90。两向都在同一次变更内**实测**过（窄向：`git grep` 默认不搜未跟踪
文件导致新建消费者不可见；宽向：注释引用判据文件名导致全量回归变红），根因是结构性的
（扫描面写死 vs 声称面是散文，且范围收缩静默），修法可落地且可判定（覆盖全部副本 +
两侧 Control + 命中即分类）。未给更高分是因为：合并的两份源记录中，宽向只实测一次，
且「边界随介质而变」这条处置规则目前只能按介质各自枚举（散文不复述原文、代码排除
纯注释行），尚无一条统一判据；复发形态每次都在换面，不能据此认为已经治尽。

## 改进方向

- **短期**：先在判据上方写下一句声称面（「这句话管多大」），再改扫描面。窄向补
  `--untracked` 与生成目录；宽向把「命中即违法」改成「命中即必须分类，且提及须带理由」。
- **短期**：给每条判据配**两条 Control** —— 正向证明能命中，反向证明能失手。只有一条时
  无法区分「干净」与「没看」。
- **长期**：凡「唯一来源 / 不再由某类文件写入 / 必须明说」这类声明，落成判据时必须同时
  落成一句可度量的范围（哪些目录、哪些副本、算不算注释与提及）。读者理解的面就是判据
  该扫的面。
- **长期**：把多副本收敛成单一来源 —— 交付清单从目录推导、副本由生成得出而非手抄。
  手抄的副本与基准之间没有对齐判据，漂移是必然的，只是何时被发现的问题。
