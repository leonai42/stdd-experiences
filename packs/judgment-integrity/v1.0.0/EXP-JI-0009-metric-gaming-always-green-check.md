## 详细描述

当「完整性」被表述为一个**覆盖比例**（例如「每条判据都必须配一条反向样本」）时，指标
就在无意中生产了它自己想要的数字。剩下的缺口在指标语言里表现为「还差几条」，也就是
**待填的坑**；而填坑最省力的做法，从来不是补一条真能失败的判据 —— 而是造一条几乎
不会失败的判据。它一旦落地就永久为绿，并且与一条好判据在外观上无法区分：同样在
登记表里有条目，同样在跑，同样从未产生过噪音。

这种判据的形态很稳定，源记录的检测触发信号把它描述得很具体：

- **变异方式写得很含糊**（「把某字段改一下」这种无从执行的描述，读的人无法判断它
  到底做了什么）；
- **断言只检查类型不检查内容**（`assert result is not None` 之类，对内容完全无约束）；
- **被变异的对象与判据的主题无关**（改了 A，却断言 B —— 两者之间没有因果关系）。

三者叠加的效果是：这条条目在登记表里占满了它该占的位置，指标达标，而它覆盖的内容
是空的。所以这不只是「测试写得不好」，而是**指标驱动的覆盖真空**：数字被满足了，
真空被填平而不是被记录。

值得注意的是这条经验的反直觉处：这里并没有人打算作弊。指标给出的是一个可计数的
缺口，而人类的默认动作是把缺口填上；「填上」与「填平」在指标上无法区分。要避免它，
必须让「做不到」有一个合法的表达方式 —— 这正是缺口登记表的作用，也是这条经验的
核心修法。

## 根因链

1. **现象层**：覆盖登记表齐全、指标达标，但其中若干条判据永远不会红，也不覆盖任何
   真实风险。
2. **直接原因**：为凑满比例，给做不到的条目写了不痛不痒的变异 + 恒真断言。
3. **为什么会这么做**：指标把缺口表达成一个**数量**，于是缺口被读作「还差几条」。
   在数量语言里，填平与填补无法区分，而填平便宜得多。
4. **为什么没有阻止**：登记表只有「有 / 没有」两栏，没有「做不到，原因是……」这一栏。
   **当「做不到」无处安放时，它只能被伪装成「做到了」** —— 这是结构问题，不是态度
   问题：即使写的人诚实，他也没有地方写下诚实的内容。
5. **本质原因**：指标只度量了「有多少条」，没有度量「每条是否有效」。任何只按比例
   衡量的完整性指标，都会同时奖励「有效覆盖」与「无效填充」—— 因为两者在比例上
   贡献相同。度量方式决定了被度量者的行为。

## 代码示例

### ❌ 错误示例

```python
# 为了凑满「每条判据都要有反向样本」，给做不到的条目写一条不痛不痒的
CONTROLS["<case-031>"] = Control(
    mutation="把 <unrelated_field> 随便改一下",   # ❌ 与判据主题无关：改了 A，断言 B
    assertion="assert result is not None",        # ❌ 恒真：任何输入都能过
)

GAPS = []          # ❌ 缺口栏为空 —— 做不到的那条被伪装成做到了
```

### ✅ 正确示例

```python
@dataclass
class Control:
    mutation: str          # 改什么
    assertion: str         # 期望它因此变红
    red_proof: str | None = None   # 一次真实跑红的记录（命令 + 输出摘要）


@dataclass
class Entry:
    case: str
    control: Control | None
    gap: str | None        # ✅ 做不到就写缺口与原因，不留空、不填平


ENTRIES = [
    Entry(
        case="<case-031>",
        control=Control(mutation="注入 <hard_violation>", assertion="assert verdict is FAIL",
                        red_proof="<cmd> → FAIL（已复跑）"),
        gap=None,
    ),
    Entry(
        case="<case-032>",
        control=None,
        gap="缺少跨切片的注入入口，本版本无法构造真实变异",   # ✅ 缺口登记成缺口
    ),
]


def test_gap_registry_matches_entries():
    # ✅ 双向核对：登记了没写、写了没登记，都要报出来
    declared = {e.case for e in ENTRIES if e.gap}
    assert declared == {g.case for g in load_gap_registry()}


def test_gaps_carry_across_versions():
    # ✅ 缺口按版本结转，不假装本轮已收口
    assert load_gap_registry(prev_version) <= load_gap_registry()


def test_every_control_can_turn_red():
    # ✅ 判据的验收标准不是「存在」，而是「能指出改什么会让它变红」
    for e in ENTRIES:
        if e.control:
            assert e.control.red_proof, f"{e.case} 的反向样本从未红过 —— 它不是判据"
```

指标口径也要跟着改：报「已收口 / 已登记缺口」两列，而不是一个覆盖比例 —— 否则下
一轮还会有人为了把比例调到 100% 而填平缺口。

## 对应失败模式

**(j) 覆盖真空（coverage_vacuum）**：有判据、有登记表、指标达标，但被覆盖的内容是
空的。这里的真空不是「忘了写」，而是**指标压力下的填平** —— 数量被满足，缺口被
伪装成覆盖。它和「判据永不返回失败」的区别在于成因：那些是可达性问题，这条是
**动机结构**问题；共同点是同一个后果 —— 一条永远为绿的判据在清单上取得与好判据
相同的位置。

不归 `hallucination`：填进来的条目不是虚构的产物，它确实存在、确实在跑，只是不
覆盖任何东西；错误在度量与激励结构，不在事实陈述。

**置信度说明**：给 0.85。检测信号具体可查（变异含糊、断言只查类型、被变异对象与
主题无关、缺口栏为空而条目数刚够），修法四条都可直接落地（缺口可登记 / 双向核对 /
按版本结转 / 「能指出改什么会让它变红」作为判据验收标准），且不需要读实现即可开查。
扣分项有二：其一，源记录 `occurrences: 1`，单次发生；其二，「为让指标好看而凑数」
这一**动机判断**在源记录里是**推断**（`provenance: ai-inferred`）—— 源记录观察到的
是形态（含糊变异 + 无关对象 + 恒真断言 + 刚够指标的条目数），而「出于指标压力」是
对形态的合理解释，不是已证实的事实，**待复核**：使用本条时应先确认「缺口登记」这条
通道确实不存在，而不是登记了却没人看 —— 后者的修法完全不同。

## 改进方向

**短期**：
- 把登记表里凑数的对照条目标出来并降级为缺口登记项：变异含糊、断言只查类型、对象与
  主题无关，三者命中任一即不构成反向样本。
- 对每条判据追问一次「改什么会让它变红」，答不出来的进缺口表。这个问题不需要跑代码，
  问题是它必须有人问。
- 指标口径改成两列（已收口 / 已登记缺口），不要用单一覆盖比例：比例会把缺口挤向
  「填平」这一侧。

**长期**：
- 让「做不到」成为一等公民：缺口登记表 + 按版本结转 + 与条目缺口字段双向核对。
  只要缺口有地方可写，就不必伪装成覆盖。
- 任何完整性指标在设计时都必须同时给出「缺口如何表达」。给不出这一条，指标就会
  生产它想要的数字，而不是生产完整性。
- 复查时优先看「从未红过的判据」，而不是「有没有判据」—— 前者是这条失败模式的
  唯一稳定入口。
