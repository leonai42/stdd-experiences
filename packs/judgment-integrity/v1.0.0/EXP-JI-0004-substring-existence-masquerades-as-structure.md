## 详细描述

**用子串存在性冒充结构成立。**判据写的是「这段正文是否还在页面上」，实现成
`body in page_text`；而模板自带的那句说明行里就含同一个字串。于是把页面上的正文
改写成别的说法之后，用例**仍然判 PASS** —— 判据的靶子不在被测结构里。

这条形态的狡猾之处在于它**不是**「忘了判」：判据在场、断言具体、失败信息也能写得很
明确。它只是把「这一条在它自己的位置上」悄悄降级成了「这个串在页面上出现过」。

存在性不蕴含归属，是这里唯一需要记住的一句话：

- 「串出现过」不蕴含「它属于哪一条」—— 页面是多条结构，「哪一条」是判据该管的维度；
- 「串出现过」不蕴含「它是正文」—— 模板自带的说明行、示例块、注释里都可能有它；
- 「串出现过」不蕴含「它是活的」—— 出现在示例里的串，不能证明正文还在。

判据在整页粒度上做子串匹配时，「哪一条」这个维度从未被检验，于是结构漂移
（条目被挤出去、正文落到别人的编号下、条目被合并）全部不可见，而用例全绿。

还有一层值得单独提：模板里那句「每条的编号与记录一一对应」本来就是**说明**，不是
判据。把判据降到条目一级时，顺手会把这句说明也落成判据 —— 于是「编号对齐」从一句
没人执行的话，变成一条会在漂移时报错的断言。**说明不是判据；只有判据才会在漂移时
报错。**

## 根因链

1. **现象层**：把页面上的正文改写成别的说法，用例仍然 PASS。
2. **直接原因**：判据比对的是字符串存在性（`body in page_text`），而那个字符串在模板
   里到处都是。
3. **为什么判据会停在这一级**：子串匹配是最省力的写法，一行就能写完，且在被检查对象
   恰好「唯一出现」时完全够用。**判据的粒度会自然停在写起来最省力的那一级**，
   而不是声称事实所需要的那一级。
4. **为什么存在性不等价于结构**：页面是「多条 + 每条一个槽位」的结构，判据声称的是
   「这一条还在页面上」。这句话里包含一个归属关系（属于哪一条），而子串匹配没有
   表示归属的能力 —— 它不是判错了，而是**没有可用于判对的表示**。
5. **为什么模板说明行会让它更假**：模板为了让填写者照抄格式，会在说明行里重复正文串
   本身（举例 / 占位）。判据于是有了一个**永久的、与被测对象无关的**命中源：即使
   正文全被清空，只要模板说明还在，判据就绿。判据的绿开始依赖一个**不由被测行为
   决定**的常量。
6. **本质原因**：**判据的粒度必须与声称事实的粒度一致。**声称的是「哪一条、在不在
   它自己的块里」，判据就必须到条目一级；否则无论断言写得多具体，它管的都不是
   那句话。

### ❌ 错误示例

```python
# <project>/<module>/page_check.py
def entry_text_preserved(page_text: str, entry_body: str) -> bool:
    # ❌ 在整页粒度上做子串匹配：只问「出现过没有」，不问「是不是这一条的正文」
    return entry_body in page_text
```

# tests/test_page_check.py
def test_entry_text_preserved() -> None:

    #   导出偶尔会超时（正文已被改写）
    page = render_proposal_page(entries=[...])

    # ❌ 正文已经被改写成别的说法，用例仍然 PASS：

    assert entry_text_preserved(page, "导出偶发失败")

### ✅ 正确示例

```python
# <project>/<module>/page_check.py
import re

ENTRY_HEADING = re.compile(r"^### (E-\d+)\s*$", re.M)


def strip_template_lines(block: str) -> str:
    # ✅ 模板自带的说明行 / 示例块 / 注释不计入正文
    kept = [
        line
        for line in block.splitlines()
        if not line.lstrip().startswith(("<!--", ">"))
    ]
    return "\n".join(kept).strip()


def entry_blocks(page_text: str) -> dict[str, str]:
    """✅ 按条目标题切块 —— 判据降到「哪一条」这一级。"""
    blocks: dict[str, str] = {}
    matches = list(ENTRY_HEADING.finditer(page_text))
    for i, m in enumerate(matches):
        start = m.end()
        end = matches[i + 1].start() if i + 1 < len(matches) else len(page_text)
        blocks[m.group(1)] = strip_template_lines(page_text[start:end])
    return blocks
```

```python
# tests/test_page_check.py
def test_entry_text_lives_in_its_own_block(entry_id: str, body: str) -> None:
    blocks = entry_blocks(render_proposal_page(entries=[...]))

    assert entry_id in blocks, f"{entry_id} 被挤出了页面"          # ✅ 条目级：先确认它在
    # ✅ 正文必须在「它自己编号」的块里；说明行已剥离，模板举例不再冒充正文
    assert body in blocks[entry_id], f"正文不在 {entry_id} 自己的块里"


def test_entry_ids_align_with_records(entry_ids: list[str]) -> None:
    # ✅ 把模板里那句「编号与记录一一对应」从说明变成判据
    blocks = entry_blocks(render_proposal_page(entries=[...]))
    assert sorted(blocks) == sorted(entry_ids), "页面上的条目编号与记录不一致"
```

## 对应失败模式

对应 `coverage_vacuum`（覆盖真空）：页面结构漂移本应有判据覆盖，实际上没有 —— 有一个
判据在场，但它管的粒度（整页子串）与声称的事实（某一条在它自己的位置上）不同，
于是「哪一条」这一整维从未被核对。

不归 `content_quality`，是因为缺陷不在生成内容的格式或风格上：页面可以完全符合模板
格式，判据依然会绿。也不归 `hallucination`：判据没有虚构任何东西，它只是把「存在」
当成了「成立」。

**置信度说明**：给 0.85。机制明确，修法落到「按条目标题切块 + 剥离模板说明行」这一级，
并且可判定 —— 「把目标文本改掉，用例必须变红」正是源记录给出的检测触发器，可以用它
自证修法有效；修法的副产品（编号对齐从说明变成判据）也来自源记录。未给更高分是因为
源记录只记 1 次发生，且**哪些行算「模板自带、不计入正文」**需要每个模板各自枚举：
源记录只示范了「说明行」这一类，示例里补充的注释 / 引用块属**按同一根因的推广 /
待复核**，落地时请按自己模板的实际构成清单化。

## 改进方向

- **短期**：把判据从整页子串匹配降到条目一级 —— 按条目标题切块，断言正文落在**它自己
  编号**的块里。
- **短期**：切块后先剥离模板自带的说明 / 示例 / 注释再比对；只要有一个不受被测行为
  决定的命中源，判据的绿就不再有信息量。
- **长期**：给每条判据问一句「它声称的事实是哪个粒度的？」判据的粒度与该粒度不一致时，
  即使断言写得再具体，也不构成覆盖。
- **长期**：把模板里那些说明性质的约束（编号对齐、必填槽位、条目唯一）逐条落成判据。
  停在说明里的约束不会在漂移时报错，而漂移是常态。
