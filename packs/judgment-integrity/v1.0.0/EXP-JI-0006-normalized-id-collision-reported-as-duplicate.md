## 详细描述

生成物里存在一个**跨区的命名空间**：同一套「前缀-区域-序号」记法同时服务于两类区域 ——
一类是**被硬校验的区**（用例区，编号必须唯一），另一类是**只作说明的区**（覆盖矩阵、
优先级列表）。同一个记法在两类区域里的合法性并不相同：在被校验的区里序号必须是独立
数字；在说明区里序号可以挂字母后缀，表示「同族的第 b 条补充」。

写的人很自然地会把同一种记法用到两类区域。而提取器为了让同族补充说明归并到一条，
会在查重之前把后缀**归一化掉**。于是两条内容不同的条目在归一化之后同名 —— 校验器
如实报「重复编号」，但文件里明摆着是两个不同的编号。

这条经验的一般形态是：**判据在对输入做归一化（抹后缀、大小写折叠、去空格、Unicode
规范化……）之后才判等，而命名约定允许的写法集合比「归一化后仍互不相同」更大**。
此时判据报出的冲突是真的（在它的等价关系下确实同名），但它给出的证据对读者是误导的：
读者看到的是一条判据在指控两件明显不同的事。归到 `contract_gap` 而不是
`coverage_vacuum`，是因为覆盖并不缺 —— 每个区都在被检查、每条条目都被数到了；
断的是**命名约定与校验规则之间的一致性契约**：约定说这两种写法都合法，规则说它们相撞。

危害方向是**假红**（false red）：它拦不住任何真实缺陷，只会让写的人多花一轮排查。
但这个方向的代价容易被低估 —— 假红会训练出一种坏习惯：看到「重复」就去改数据，
而不是去问判据的等价关系是什么。一条经常发出误导性证据的判据，最终会被绕过，
而绕过的方式看起来完全合理（「两个编号确实不同，改掉一个就好了」）。

## 根因链

1. **现象层**：校验器报某区编号重复，而文件里两个编号在肉眼上明显不同。
2. **直接原因**：提取器在查重前把字母后缀归一化掉，两条不同条目归一化后同名。
3. **为什么会出现**：两类区域共用一个命名约定，而只有一类挂唯一性硬校验。后缀记法在
   说明区合法，被顺手带进了被校验区 —— 在那里，归一化把它变成了另一个编号的别名。
4. **为什么没人拦住**：命名约定的「合法写法集合」与校验规则的「等价类划分」没有写在
   同一处，也没有一份可执行断言把两者绑起来。约定是散文，规则是代码，两者各自演化；
   只要没人同时读这两处，背离就不会被发现。
5. **本质原因**：**判据的等价关系没有暴露给被判的对象**。任何「先归一化再判等」的
   校验器都是一个隐式的等价关系；这个关系必须与命名约定同源、可见、可被引用 ——
   否则它只会在撞上时以「重复」的形式出现，而不会以「你用了等价写法」的形式出现。

## 代码示例

### ❌ 错误示例

```python
# 校验器：提取编号 → 抹掉后缀 → 查重
ID_RE = re.compile(r"[A-Z]{2,}-[A-Z]{2,}-\d{3}[a-z]?")

def duplicate_ids(plan_text: str) -> list[str]:
    seen, dups = set(), []
    for raw in ID_RE.findall(plan_text):
        key = re.sub(r"[a-z]$", "", raw)   # ❌ 隐式等价关系：<AREA>-003 与 <AREA>-003b 视为同一条
        if key in seen:
            dups.append(key)               # ❌ 只报归一化后的编号，不报原始写法
        seen.add(key)
    return dups


# 被检查的正文里，两条内容不同的用例：
#   <AREA>-003    正常路径
#   <AREA>-003b   余额不足路径        ← 后缀记法在说明区是合法的，这里被顺手带进了用例区
# → 报「<AREA>-003 重复」，而文件里两条编号明显不同
```

### ✅ 正确示例

```python
# 约定：被校验区只认「前缀-区域-三位数字」这一种写法 —— 归一化在该区是恒等变换
CASE_ID_RE = re.compile(r"^[A-Z]{2,}-[A-Z]{2,}-\d{3}$")
# 说明区允许后缀，但后缀只在说明区成立
NOTE_ID_RE = re.compile(r"^[A-Z]{2,}-[A-Z]{2,}-\d{3}[a-z]$")


def collect_case_ids(case_region_text: str) -> list[str]:
    raw = re.findall(r"[A-Z]{2,}-[A-Z]{2,}-\d{3}[a-z]?", case_region_text)
    offenders = [i for i in raw if not CASE_ID_RE.match(i)]
    if offenders:
        # ✅ 报「你用了等价写法」本身，而不是报它撞了谁 —— 报错与根因同源
        raise NamingError(
            f"用例区出现带后缀编号 {offenders}；后缀记法只允许出现在说明区"
        )
    return raw


def report_duplicates(ids: list[str]) -> list[str]:
    groups: dict[str, list[str]] = collections.defaultdict(list)
    for raw in ids:
        groups[raw].append(raw)
    dups = {k: v for k, v in groups.items() if len(v) > 1}
    if dups:
        for key, raws in dups.items():
            raise DuplicateError(
                f"编号重复：归一化后同为 {key}；原始写法 {sorted(raws)}"   # ✅ 两面都给
            )
    return []
```

改名之后还要 grep 旧的后缀编号，清理全仓引用：文档、任务清单、测试 docstring 里的
编号标注都可能停在旧名字上。

## 对应失败模式

**(k) 契约断层（contract_gap）**：断的是「命名约定 ↔ 唯一性校验规则」之间的契约。
约定声称这套记法在两个区都合法，规则在被校验区只承认其中一个子集，而两者的桥梁
（归一化规则）只存在于提取器的代码里。契约的一侧是散文，另一侧是代码，中间没有
可执行断言 —— 于是背离必然发生，并且只会在数据撞上时以「重复」这一误导性形式暴露。
不归 `coverage_vacuum`：覆盖并不缺失，被检查的对象一个都没漏；缺的是两条规则之间的
一致性。

**置信度说明**：给 0.80（本包最低）。触发信号清晰（报「重复」而两条编号肉眼不同）、
归因方向明确（归一化），但有三处扣分：其一，源记录 `occurrences: 1`，单次发生；
其二，**「提取器会归一化后缀」在源记录里是推断**（`provenance: ai-inferred`），
源记录未附提取器的实际归一化规则，也未给出复现记录 —— 使用本条前请先核对自己
工具链里的提取规则是否真的抹后缀、抹的是哪个字符集，**待复核**；其三，源记录未标注
`language`（本条的 `language: python` 是按包内一致性指定的），而这条教训本身与语言
无关，任何「先归一化再判等」的校验器都适用。

## 改进方向

**短期**：
- 被校验区改成独立数字编号，去掉字母后缀；grep 旧后缀编号清理全仓引用
  （文档 / 任务清单 / 测试 docstring 里的编号标注）。
- 让判据的报错同时输出「原始写法 + 归一化结果」：报错的信息量必须等于判据的依据，
  否则读者只能靠猜去对齐判据的等价关系。
- 把这一类报错当成命名问题而不是数据问题：出现「归一化碰撞」时先把命名约定改掉，
  而不是先改数据。改数据只消掉了信号，等价关系还在。

**长期**：
- 把归一化规则抽成单一来源的显式函数（例如 `normalize_id()`），命名约定文档与校验器
  都引用它。约定与判据同源之后，碰撞会在命名的那一刻就被写的人看到。
- 给任何「先归一化再判等」的校验器补一条自查：**等价类的定义必须被写下来**，并且
  被归一化掉的那些写法在被校验区里必须是非法的 —— 两者缺一，这个校验器就还会以
  误导的形式报错。
- 把「判据报错给出的证据是否等于判据的依据」纳入评审清单。这一条比它看起来更普遍：
  任何「折叠、截断、取整、归一化之后再比较」的判据，都有同样的报错不可自证的风险。
