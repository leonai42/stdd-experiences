## 详细描述

对外产物（报告及其附录）里有若干**读者可见**的字段，用于说明一条读数的「口径」——
即这个数字到底是什么。这类字段是读者判断「两个市场的报价能不能相减」的唯一依据，
因此它的文本本身就是一个**可比性判据**，不是装饰。

问题在于同一个概念被登记在多个地方，而每一处都能渲染进对外产物：

- 来源注册表：登记每个数据源的基本信息；
- 口径层模式表 / 基准口径表：按类别给出默认口径；
- 口径解析器：按每条现货记录算出实际使用的口径。

其中只有一处写明了「此处只写读者可读的口径语」这条规矩，其余处违背它、且没有任何检查
因此变红。实测结果是三条主锚的口径串形态各异，其中两条还夹带了估算过程与结论
（形如「<供需估算> → <方向性结论>」）。

后果有两个，且都不轻：

1. 读者会把估算读成报价的一部分 —— 估算进入了本该只描述「价格是什么」的位置；
2. 读者无从判断几个市场可不可比 —— 三条串形态不同，读者无法知道它们的差别是口径差别
   还是口径描述方式差别。

## 根因链

1. **现象层**：同一字段在多处渲染出不同文本，其中部分文本夹带估算与结论，读者误读。
2. **直接原因**：同一概念在多个消费方各存一份字符串，且各处的写法不受任何约束。
3. **为什么规则没有生效**：规矩写在注释里而不是可执行断言里。注释不是判据 ——
   它不参与任何检查、不会因违反而变红，且写在其中一处时，还会给人「规矩已经定过了」
   的错觉，反而降低了对其余几处的审查强度。
4. **本质原因**：口径串是**读者侧的可比性判据**，但它在实现侧被当成了自由文本。一旦
   判据是自由文本，系统的可比性就没有任何保障 —— 两条读数是否可以相减，取决于两个
   字符串碰巧写了什么。这一点与「价格是估算还是报价」无关，是判据形态的问题：
   判据必须是可判定的（同形 / 逐字相等），不能是自然语言。

## 代码示例

### ❌ 错误示例

```python
# 来源注册表（一处）
source_registry = {
    "anchor_a": {"caliber": "<market>市场价（贸易自提·区间中值）"},   # 唯一守规矩的一处
}


# 口径层模式表（另一处，可渲染进对外产物）
caliber_defaults = {
    # ❌ 形态不同：用了括号与顿号，且夹带了估算过程
    "anchor_b": "<market>现货（估算）",
    # ❌ 夹带推理箭头与结论 —— 读者会把结论读成报价的一部分
    "anchor_c": "<供需估算> → <方向性结论>",
}


# 口径解析器（第三处，也能渲染进对外产物）
def resolve_caliber(record):
    # ❌ 又一种形态；规则只写在别处的注释里，这里没人核对
    return record.get("caliber") or "<fallback_text>"


# 测试目录里没有任何一条用例钉住这些串
```

### ✅ 正确示例

```python
# 口径串统一为同一句口径语，由单一来源产出，各处只引用不另写
CALIBER_TEMPLATE = "{market}市场价（贸易自提·区间中值）"

ANCHOR_MARKETS = {"anchor_a": "<market_a>", "anchor_b": "<market_b>", "anchor_c": "<market_c>"}


def resolve_caliber(anchor_id: str) -> str:
    # ✅ 只描述「价格是什么」，不承载估算与结论
    return CALIBER_TEMPLATE.format(market=ANCHOR_MARKETS[anchor_id])


# ✅ 同形断言：对同一族的每个字段断言完全相等（不是包含关键词）
def test_all_anchors_share_identical_caliber_shape():
    calibers = {aid: resolve_caliber(aid) for aid in ANCHOR_MARKETS}
    assert len(set(calibers.values())) == 1, calibers     # 逐字相等，不是「包含某关键词」


def test_caliber_contains_no_estimate_or_conclusion():
    for aid in ANCHOR_MARKETS:
        text = resolve_caliber(aid)
        # ✅ 估算与结论不属于这个字段，它们的归宿是报告正文或注释
        for token in ("估算", "预计", "判断", "结论", "→"):
            assert token not in text, (aid, text)
```

两条断言缺一不可：第一条保证多处登记的串**形态一致**（可比性有保障），第二条保证该
字段**只描述价格**（不会被估算污染）。只做第二条时，三处仍可能写出三种形态；只做
第一条时，三处可以一致地夹带结论。

## 对应失败模式

**(k) 契约断层（contract_gap）**：这里断裂的是「读者可见字段的登记处与它声明的规矩之间
的契约」。同一个字段有多个提供方（注册表 / 模式表 / 解析器），它们对外都代表同一个
概念，但各自的产出契约不同：只有一处约定「只写读者可读的口径语」，其余处没有这条约定，
而消费方（读者、下游取数逻辑）却按统一口径去读它们。归到 contract_gap 而不是
content_quality，是因为问题不在于串写得不够漂亮，而在于**同一概念的多个提供方之间没有
共同的契约** —— 可比性判据应当逐字对齐（这是可判定的），而它现在是自由文本（不可判定）。
这类断层的一个典型标志就是：没有任何检查会因为违反而变红。

**置信度说明**：给 0.80。源记录把失效机制说得很清楚（多处登记、只有一处写了规矩、
其余处违背且无检查变红），并给出了可直接落地的修复形态（同形断言 + 逐字相等，而不是
包含关键词），这一点使条目具备可执行性。未给更高分有两个原因：一是源记录只记了 1 次
发生；二是「统一为哪一句口径语」需要业务侧先确定口径优先级，属于本条目无法单方面
判定的部分（源记录同样把它留给使用者决定）。

## 改进方向

**短期**：
- 盘点所有读者可见字段的登记处，逐处确认它们是否都遵守同一句口径语；不遵守的，
  改为引用单一来源，而不是各写一份。
- 给每个字段族补两条断言：形态逐字相等、且不含估算 / 结论类词与推理箭头。
  这两条断言是本模式唯一的自动化防线。
- 把已经进入对外产物的口径串记录下来（含历史产物），确认读者看到的三条主锚是否已经
  真的被误读 —— 口径不一致的存量产物需要单独说明，不能只修代码。

**长期**：
- 把口径串从「多处各存一份字符串」收口为单一来源产出：各处只引用模板，不自行拼写。
- 确立判据可判定性原则：凡用于「判断两条读数能否相比」的文本，必须是同形可逐字比对的，
  不得是自然语言自由文本。规则要么写进断言，要么不写 —— 写在注释里的规则等于没有规则。
- 把估算与结论的归宿固定下来（报告正文或注释），并在渲染层做字段级白名单：口径字段
  只允许价格描述语言。
