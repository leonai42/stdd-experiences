# rejected/ — 已拒绝的经验

本目录存放**判定为不成立**的经验记录：记录本身不能作为一条可复现的社区经验。

与 `out-of-scope/` 的区别见 [`../out-of-scope/README.md`](../out-of-scope/README.md)：
`rejected/` 是「记录不成立」，`out-of-scope/` 是「记录成立但受众不对」。

每条记录的 frontmatter 末尾带一个 `audit` 块，写明 `verdict: reject`、所属桶与具体理由。
保留原文件（不删除）是为了让拒绝决定可复核 —— 否则「为什么拒了这条」只存在于审计报告里。

## 一条拒绝记录的判定依据

拒绝**不依据记录的形式合规性**，而依据其内容的真实性 / 可迁移性 —— 这两组例子正好相反：

- `EXP-2026-0001` 与 `EXP-e0f388bc14a2` 的必填字段**完全齐备**，格式上挑不出毛病，
  但内容是合成的 / 绑死某个项目的；
- `EXP-ps20` 则连字段都是占位符。

所以「字段齐全」不等于「应当入池」。反过来，缺字段的记录也不必然拒绝 ——
那属于「退回补齐」（见 `pending/` 里 C 桶的 7 条），不是拒绝。
